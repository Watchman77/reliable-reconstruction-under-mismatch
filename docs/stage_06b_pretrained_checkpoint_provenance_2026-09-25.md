# Stage 06B pretrained checkpoint provenance review (25 September 2026)

Status: **training-source families documented; image-level overlap unresolved; 06B gate remains pending**. This review uses the frozen Stage 05 component receipts, official model documentation and training configurations. It does not inspect Stage 06 reconstruction outcomes or unseal Stage 05.

## Scope and evidence standard

The 994-source RAISE-1k eligible manifest resolves duplicate identities within the acquired source pool and its Stage 05 original-image screen. It cannot establish that a pretrained model never saw an RGB rendering, crop, resized copy, or internet repost of a RAISE source. A checkpoint SHA-256 identifies bytes, but does not itself identify the photographs used to train those bytes. The source lists below describe the authors' reported training; they are **not** a verified image-level lineage for each checkpoint.

## Decision for the next development step

For a development-only DiffPIR smoke test, assess the official **256×256 class-unconditional ImageNet** prior first because the RAISE pool contains varied natural scenes, while the shipped deblur default is FFHQ face-specific. This is a test order, **not** a checkpoint freeze or a claim of no training overlap. Override the upstream FFHQ default explicitly and record the effective model name; then pin the exact repository commit, downloaded checkpoint SHA-256 and bytes, source URL, NFE, solver parameters, environment and failure/compute receipt before comparing solvers. Do not use a face model accidentally through the upstream default.

To move the provenance gate, seek image-level source lists or authors' confirmation for the **actual** DRUNet and FBCNN weights and whichever DiffPIR weight is selected. Where source images are available under their access terms, compare all 994 RAISE source renders against the relevant training photographs and derivatives using multiple render sizes, robust visual retrieval, and manual adjudication of flagged pairs; log dataset release/version, reference file digest, matching rule, candidates and decisions. A filename search, an exact RAW hash search, or a negative 64-bit dHash screen alone does not exclude transformed copies. Freeze any overlap exclusions in a versioned role manifest **before** related modeling outcomes are viewed. If exact training lineage cannot be obtained, record the residual risk explicitly, constrain claims of unseen external data, and have the protocol owner make a documented go/no-go decision before confirmatory evaluation; do not silently call overlap proven absent.

Other 06B tasks remain pending in the [integrity review](stage_06b_raise_integrity_and_overlap_review_2026-09-25.md) and [execution checklist](stage_06_execution_checklist.md), including publisher access/retrieval documentation and universal loader enforcement. **No independent-test result is authorized by this review.**
